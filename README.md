# 高企申报工作台

一个本地优先、开源、可自行部署的广东高企数据与申报工作台。首页以三维地球和广东 21 地市动态地图呈现公开名录与最新政策，之后可进入资料审核、智能整理、文件起草和政策指南。

项目不承诺“材料一定符合要求”或“申报一定通过”。它用于发现可以自动识别的问题，帮助经办人缩短初审时间，最终判断仍须由企业和技术、财务、人事负责人以及主管认定机构完成。

## 独立工作界面

| 页面 | 功能 |
| --- | --- |
| [3D 指挥中心](index.html) | 三维地球、广东 21 地市名录地图、最新政策与功能入口 |
| [数据工作台](workspace.html) | 项目状态、文件数量、结构分、必要类别覆盖和最近资料 |
| [资料审核](audit.html) | 拖入文件、文件夹或 ZIP；解析 PDF/DOCX/XLSX；分类、重复检查、敏感信息检查和硬门槛自查 |
| [智能整理](organizer.html) | 按主体、IP、RD、PS、人员、财务和收入重组资料；生成建议命名、导出 CSV/Markdown |
| [文件起草](draft.html) | 基于企业真实结构化信息生成研发项目、产品技术、成果转化和创新能力说明草稿 |
| [政策指南](guide.html) | 八项认定条件、100 分评分、材料清单、退件风险与官方来源 |
| [FORESTS ONCHAIN](forest.html) | 参照视频重建的黑白极简 3D 森林交互实验页 |

## 已实现的资料能力

- 一次选择多个文件、整个文件夹或 ZIP 压缩包
- 在浏览器本地保存文件、抽取文字和审核结果
- 自动识别 12 类资料：申请、主体、IP、研发、产品、转化、人员、财务、税务、合同收入、研发管理和其他
- 对 11 个必要材料类别进行覆盖检查
- 检查解析失败、扫描件待 OCR、重复文件、低置信度分类和潜在敏感信息
- 识别企业指标：注册年限、核心 IP、科技人员、研发费用、境内研发费用、高新收入和合规底线
- 允许人工修改分类、查看抽取文本、下载原件和删除文件
- 按 IP → RD → PS → 合同收入形成证据地图
- 导出审核报告、材料整理方案和 CSV 整理表
- 四种文书草稿：研发项目、产品技术、成果转化、创新能力
- 草稿保存、继续编辑、复制与 Markdown 导出

## 广东三维指挥中心

- 全屏 Three.js 三维地球，支持拖拽旋转和滚轮缩放
- 广东 21 个地级市真实 GeoJSON 边界与可交互城市地图
- 2025 年高新技术企业认定/备案名录城市分布
- 城市点击联动三维地球聚焦、数量详情和政策入口
- 省级 2026 年认定通知、时间调整和城市主管部门入口
- 响应式移动端城市选择器

数据口径：

- 广东省 2025 年认定名单共 11,871 家，不含深圳。
- 深圳采用 2025 年第一批备案名录 7,249 家，单独列示。
- “2025 年名录数”不是当前有效存量。有效存量会随复审、迁移、撤销等动态变化。

详细来源和统计方法见 [data/README.md](data/README.md)。

## 沉浸式业务页面

除指挥中心外，资料审核、智能整理、文件起草、政策指南和资料工作台都使用同一套沉浸式交互语言：

- 全屏杂志式标题和景深空间
- 五个页面各自独立的程序化 3D 场景
- 鼠标视差、滚动揭示、卡片倾斜和指针光感
- 页面转场、动态进度和系统状态信息
- 移动端降级与减少动态支持

这套体验使用 Three.js 程序化生成，不包含视频原作者的素材。

## FORESTS ONCHAIN

`森林交互/` 是独立的实验页面，复刻参考视频中的巨型断行标题、黑白与森林绿配色、平滑滚动、章节叙事、极简数据底栏和空间穿越感。

页面用 Three.js 程序化生成低多边形森林，包含滚动镜头移动、鼠标视差、拖拽观察、章节淡入和模拟链上数据。页面不接入真实区块链，也不包含参考视频素材。

## 启动

需要 Node.js 20 或更高版本。安装依赖后运行：

```bash
npm install
npm start
```

访问终端显示的 `http://127.0.0.1:4173`。

不要把页面作为 `file://` 直接双击打开：ES 模块和 PDF 工作线程会被浏览器安全限制阻止。`npm start` 只是提供本地静态文件，不接收或上传企业资料。

## 发布到 GitHub Pages

仓库内置了 `.github/workflows/pages.yml`。把项目推送到 GitHub 的公开仓库后：

1. 打开仓库 `Settings → Pages`。
2. 在 `Build and deployment` 的 Source 中选择 `GitHub Actions`。
3. 运行 `Deploy GitHub Pages` 工作流，或向 `main` 分支推送新提交。
4. 部署完成后，网址通常为 `https://<用户名>.github.io/<仓库名>/`。

工作流会安装依赖、构建 Three.js 浏览器包、运行测试并部署精简后的静态站点。

## 文件与隐私

- 文件解析、分类和审核在浏览器中完成。
- 当前版本没有后端数据库、统计脚本或远程解析接口。
- 文件 Blob、抽取文本、企业指标和草稿保存在 IndexedDB。
- 清除浏览器站点数据会删除工作区，重要草稿应另行导出。
- 仅在本机受控环境中处理真实资料。
- 不应把身份证号、完整社保名单、客户合同、发票、银行流水、系统账号或未脱密技术资料提交到公开仓库。

## 支持格式

可直接抽取正文：

- PDF（有可复制文字的版本）
- DOCX
- XLSX / XLSM
- TXT、Markdown、CSV、JSON、XML、HTML
- ZIP 中的上述文件

当前限制：

- 图片和扫描 PDF 会标记“待 OCR”，不会被假装为已审核。
- 旧版 `.doc` 和 `.xls` 会提示另存为 `.docx` / `.xlsx`。
- PDF 中扫描图片、表格版式和印章不会自动识别。
- 文件分类基于文件名和正文关键词，低置信度结果需要人工确认。
- 指标是否达标只做数据初筛，不能替代专项审计、纳税申报和官方审核。
- 草稿模板只组织已填写事实，不会补造专利、指标、收入或研发成果。

详细能力边界见 [工作台架构](docs/ARCHITECTURE.md)。

## 测试与检查

```bash
npm test
npm run check
npm audit --omit=dev
```

- `npm test` 验证门槛、评分、分类、敏感数据识别、审核规则和起草模板。
- `npm run check` 检查多页面、本地依赖、导航、材料类别和政策基准。
- `npm audit --omit=dev` 检查已安装解析依赖的已知漏洞。

浏览器测试覆盖：

- 演示工作区初始化
- 文件夹外的 TXT、ZIP 多文件展开
- DOCX、XLSX 和真实 PDF 文本抽取
- 审核、整理和起草页面
- 桌面和 390px 手机宽度
- 3D 地球 WebGL 渲染、21 个城市边界、城市切换和移动端选择器

## 政策口径

当前全国性规则以以下文件为基准：

- 《高新技术企业认定管理办法》，国科发火〔2016〕32号
- 《高新技术企业认定管理工作指引》，国科发火〔2016〕195号

政策核验日期为 `2026-10-23`。截至该日期，部分地方 2026 年正式申报通知仍明确引用上述文件。本项目没有把自媒体流传但未在主管部门正式文件或当年度地方通知中确认的“评分重大调整”写入计算规则。

地方批次、系统入口、附件模板、审计报告查验方式和奖补政策可能不同，必须在申报前复核当地当年度通知。详见 [政策说明](docs/POLICY-NOTES.md)。
