# 贡献指南

感谢参与“高企申报手册”。项目最重要的资产是可信、可核验、可执行的申报信息。

## 开始之前

1. 搜索已有 Issue，避免重复。
2. 小修改可以直接提交 Pull Request；涉及规则变化或产品方向的大修改，请先开 Issue 说明。
3. 读取 [政策核验与维护说明](POLICY-NOTES.md)。
4. 不在 Issue、PR、测试或示例中加入真实敏感资料。

## 本地开发

项目无需安装第三方依赖。Node.js 20 以上版本可运行测试：

```bash
npm test
npm run check
npx --yes serve .
```

## 可以贡献什么

- 官方政策更新和可核验来源
- 计算逻辑修复与边界测试
- 材料证据链和风险提示改进
- 移动端、键盘操作、屏幕阅读器和打印体验
- 脱敏后的模板结构与常见问题
- 文档纠错和简洁性改进

## 政策类贡献要求

必须提供：

- 官方原文链接
- 发布机关
- 文号（如有）
- 发布日期与生效日期
- 适用地区和年度
- 受影响的项目、计算或材料
- 与现有口径的差异说明

不接受仅依据培训文章、自媒体解读、无来源截图或“内部消息”的变更。

## 代码与数据约定

- 页面不引入跟踪脚本、广告或非必要第三方资源。
- 真实填报数据不得上传；演示数据必须明确标为虚构。
- 计算规则与 UI 分离，新增规则应补充自动化测试。
- 保持静态站点可直接部署，不依赖后端。
- 使用语义化 HTML、可见焦点状态和可访问名称。
- 文案优先说明“需要证明什么”和“如何核验”。

## 提交 Pull Request

PR 描述请包含：

- 改了什么
- 为什么修改
- 如何验证
- 如属政策更新，附官方来源和适用日期
- 是否涉及数据、计算或页面结构变化

提交前运行：

```bash
npm test
npm run check
```

## 隐私与保密

不要提交以下内容：

- 身份证号、手机号和私人住址
- 完整社保名单或工资明细
- 未公开客户合同、发票、银行流水
- 未脱密研发资料、源代码产权证据
- 申报系统账号、密码、API Key 或访问令牌

示例材料应删除主体名称、金额、联系方式和可识别个人身份的信息。

## 行为准则

参与项目即表示同意遵守 [行为准则](../CODE_OF_CONDUCT.md)。
